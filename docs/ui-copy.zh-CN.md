## 示例文章一：为每页设置自己的 canonical URL

英文标题：Give every page its own canonical URL。

摘要：一个小小的元数据决策，告诉搜索引擎你希望索引页面的哪个版本。

- 从页面本身开始，而不只是域名：canonical 标识一份内容的首选地址。首页、文档和各篇文章描述不同内容，因此应该各自指向自己的首选 URL。
- 保持 URL 一致：使用生产 origin，保留页面路径，并统一结尾斜杠约定。追踪参数不改变内容时，可以指回不带参数的文章地址。
- 检查响应：打开页面源代码找到 canonical 链接，与正在访问的页面、sitemap 项和 Open Graph URL 比较；它们应该指向同一页面。

## 示例文章二：让下一个链接值得分享

英文标题：Make your next link worth sharing。

摘要：根据与页面一致的标题和描述，制作实用的 Open Graph 分享卡。

- 同一个身份，多种展示位置：页面标题帮助访客理解内容。社交卡将这个身份带到聊天、信息流或收藏链接中。文案应具体对应正在分享的页面。
- 生成真实图片：内置端点使用 Next.js ImageResponse 返回 1200×630 图片。直接打开端点，检查标题是否合适以及响应是否为图片。
- 测试已发布地址：社交平台需要从公开 URL 抓取图片。Preview 可能需要认证，所以发布分享前应检查最终公开图片。
